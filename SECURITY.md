# Security Policy · Política de Segurança

## Current status

Igor Cloud is an early-stage project. It does not currently provide a production file-storage service. Security principles documented in this repository are design intentions, not a claim that application controls have already been implemented.

## Reporting a vulnerability

Please do not publish credentials, private files, access tokens or exploitable vulnerability details in a public issue.

Use GitHub's private vulnerability reporting feature for this repository if it is enabled. If private reporting is unavailable, contact the repository owner through the contact information on the GitHub profile and share only the minimum information needed to establish a safe communication channel.

## Scope

Reports are most useful when they identify a concrete security risk in code or configuration that exists in this repository. The current repository is primarily documentation, so reports about unimplemented features should be framed as design concerns rather than confirmed vulnerabilities.

## Responsible disclosure

Please allow reasonable time for investigation and remediation before publicly disclosing a confirmed vulnerability. Do not access, modify or delete data that does not belong to you while testing.

## Português

A segurança é uma consideração fundamental do Igor Cloud. Como o projeto ainda está em planejamento e documentação, esta política descreve o processo de comunicação responsável; não representa a existência de um serviço em produção.

### Como comunicar uma vulnerabilidade

Não publique detalhes de vulnerabilidades não corrigidas em issues públicas.

Use os recursos privados de contato ou de relatório de vulnerabilidade disponibilizados pelo GitHub para este repositório. Se esses recursos não estiverem disponíveis, entre em contato com o mantenedor por um canal privado associado ao perfil do GitHub.

Ao relatar um problema, inclua, quando possível:

- Uma descrição objetiva da vulnerabilidade.
- As etapas necessárias para reproduzi-la.
- O impacto potencial e os componentes afetados.
- Evidências mínimas e não sensíveis.

Não inclua senhas, tokens, dados pessoais ou arquivos de terceiros no relatório.

### Tratamento e divulgação

Os relatos serão analisados conforme a capacidade de manutenção do projeto. A divulgação pública deverá ocorrer somente após a avaliação do problema e a definição de medidas apropriadas. Não há prazo de resposta ou correção garantido neste estágio inicial.

### Escopo atual

O repositório não contém atualmente um serviço funcional de armazenamento. A ausência de uma aplicação executável não elimina a importância de relatar exposição acidental de segredos, problemas na documentação ou riscos relacionados ao desenvolvimento.
