# Contributing · Contribuindo

Thank you for your interest in Igor Cloud.

## Current stage

Igor Cloud is in an early documentation and planning stage. The application is not yet runnable, and contribution workflows may evolve as the codebase is established.

## Before proposing a change

- Check the README and architecture notes to understand the current scope.
- Keep proposals focused and explain the problem they solve.
- Do not describe planned functionality as implemented.
- Do not include credentials, tokens, personal files or other private data.

## Suggested contribution process

1. Open an issue to discuss a substantial feature or architectural change.
2. Keep changes small and focused.
3. Include or update documentation when behavior or technical decisions change.
4. Add tests when executable application code exists.
5. Explain any security, compatibility or migration implications.

## Code and documentation standards

- Prefer clear names and maintainable structures.
- Validate untrusted input on the server.
- Keep secrets out of source control.
- Document configuration variables without publishing their values.
- Update the roadmap only when the corresponding work is genuinely complete.

## Language

Issues and documentation may be written in English or Portuguese.
